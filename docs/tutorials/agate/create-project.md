# Create and tour a project

Create a project inside a workspace, choose its Stylebook, and tour the settings
that control its flows and integrations.

!!! note "Tutorial outline"
    Detailed steps and screenshots are still to come.

## You'll learn

- How workspaces, projects, and Stylebooks relate.
- What the project overview measures.
- Where flows, runs, models, integrations, API keys, and the system prompt live.
- Which project choices inherit organization settings and which remain fixed.

## Before you begin

You need access to the destination workspace and permission to create a
project. If the organization has several Stylebooks, decide which one the
project should use before continuing.

## Planned walkthrough

1. Open a workspace and choose **Add Project**.
2. Enter the project name and confirm its generated slug.
3. Choose the permanent project Stylebook when that option is available.
4. Tour project activity and estimated model-cost summaries.
5. Open the **Flows** and **Runs** tabs.
6. Enable project models and choose generative and embedding defaults.
7. Review the project system prompt.
8. Inspect integration inheritance and add a temporary override.
9. Open the **API** tab and review key ownership and scopes.
