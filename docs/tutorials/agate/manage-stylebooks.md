# Create and manage Stylebooks

Create a Stylebook, choose the organization default, manage editor access, and
understand the safeguards around renaming, copying, and deletion.

!!! note "Tutorial outline"
    Detailed steps and screenshots are still to come.

## You'll learn

- When separate Stylebooks are useful and when projects should share one.
- How the organization and workspace defaults affect project creation.
- Why a project's Stylebook cannot be changed after creation.
- What the Stylebook copy workflow includes and excludes.

## Before you begin

You need organization-administrator access. Decide what editorial boundary the
new Stylebook represents and which members should be allowed to edit it.

## Planned walkthrough

1. Open the organization **Stylebooks** administration page.
2. Create and name a Stylebook.
3. Set or change the organization default.
4. Assign Stylebook editor access from **Users**.
5. Rename the Stylebook and confirm navigation updates.
6. Export a Stylebook copy and preview an import.
7. Review deletion impact and replacement requirements without deleting
   active project data accidentally.
